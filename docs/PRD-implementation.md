# BattleFeed PRD v1.0 구현 기록

## 범위와 진행 상태

사용자와 먼저 항목별 해석을 공유한 뒤, **서버·DB 구현 및 로컬 검증부터 진행**하기로 했다.
Node.js 24 내장 SQLite와 HTTP 서버를 사용하며 데이터는 `data/battlefeed.sqlite`에 저장된다.
기존 데모 데이터·브라우저에서 임의로 지급하는 BP를 제거했다. 운영 GitHub Pages에는 아직 이 변경을 배포하지 않는다.

**실제 광고 사업자 연동과 운영 서버 배포는 미완료다.** 이를 완료하기 전에는 운영 환경에서 PRD 전체를 충족한다고 볼 수 없다.

## PRD에 없거나 불명확한 부분의 명시적 선택

- **기간 랭킹**: 글 작성일이 아니라 기간 내 배틀 이벤트 점수로 계산한다. 해당 기간에 새로 작성한 0점 글도 발견 가능하게 포함한다. `최신`은 해당 기간 작성글을 작성 시각순으로 표시한다.
- **급상승**: 선택 기간의 각 이벤트에 대해 `방향별 점수 / (1 + 경과 시간[시간])`을 더한다. 방향은 지지 +, 반대 −. 이는 PRD에 공식이 없어 선택한 MVP 규칙이다.
- **최신 코인 순서**: 그룹 내 가장 최근 글의 작성 시각. 나머지 분류는 그룹 내 해당 지표 합계. 이는 앞서 요청한 두 피드 간 정렬 공유를 따른다.
- **BP 사용 시점**: 게임 시작 시 차감. 중도 종료는 환급하지 않는다. 취소 API로 진행 세션을 닫을 수 있다. 재시도는 같은 요청 ID를 사용한다.
- **새 계정 BP**: 0으로 시작하고 첫 출석으로 참여 BP를 받는다.
- **핀 비용**: 기본 1 BP. 수정·삭제는 차감하지 않는다. 거래 가능한 코인·외부 링크는 기존 기능으로 남기되 선택 사항이다. 플랫폼 안에서 거래하지 않는다.
- **시간대**: 가입 시 계정에 기록한다. 현 버전은 임의 시간대 변경을 노출하지 않아 출석 날짜 조작에 의한 반복 지급을 제한한다. 피드 조회 시간대는 조회용으로만 사용한다.
- **이미지**: 최대 2MB PNG/JPEG/WebP 한 장, 로컬 MVP에서는 DB에 data URL로 보관한다. 운영 규모가 커지면 객체 저장소로 옮긴다.
- **코인 목록**: 기존 목록에 SL을 추가했다. 표시된 목록은 실시간 시가총액 API가 아니다.

## 부정행위 방지의 한계

서버가 직접 점수를 계산하고 불가능한 입력을 거부하지만, 브라우저가 제출하는 입력 기록의 진위까지 완벽히 증명하지는 않는다.
정상 범위의 자동화 입력은 통계·패턴 기록을 통해 검토해야 한다. 플래그는 자동 제재가 아니다.
완전한 봇 방지나 운영 규모의 보안 감사를 완료했다고 주장하지 않는다.

## 광고 연결 계약

`createService({ ads })`에 다음 어댑터를 주입한다.

- `ads.start({ id, userId })`: 실제 사업자 광고 세션을 만들고 `{ url }` 등 실행 정보를 반환한다.
- `ads.verify(rawBody, headers)`: 해당 사업자 공식 서명 검증 및 완료 상태 확인 후 `{ sessionId, transactionId }`를 반환한다. 검증 실패 시 예외를 발생시켜야 한다.
- 실제 사업자 콜백을 `/api/ads/callback`으로 연결한다. 보상액을 클라이언트에서 받지 않는다.
- `server/index.js`는 현재 어댑터를 주입하지 않으므로 광고 보상 UI가 비활성이다. 테스트의 검증기는 운영용이 아니다.
- 광고 업체의 승인된 광고 단위·키·공식 SDK가 없으므로 실제 광고 재생과 운영 콜백 검증은 아직 구현/검증하지 못했다.

## 운영 전 남은 작업

1. 운영 서버·도메인·HTTPS·지속 DB 디스크와 백업 정책 확정.
2. 광고 사업자 선정 및 위 계약에 맞춘 공식 SDK/서명 검증 구현.
3. 해당 환경에서 휴대폰 PWA 설치·네트워크 변경·운영 광고 완료 테스트.
4. 배포 시 정적 프런트엔드와 API를 동일 사이트로 제공하거나 역방향 프록시 구성. 현재 세션 쿠키는 SameSite=Lax다.
5. SQLite 단일 서버 MVP의 부하·동시성 측정. 대규모 서비스에는 쿼리 집계 최적화·페이지네이션·다중 서버용 DB 이관이 필요하다.
