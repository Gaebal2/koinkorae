# 홈 피드와 배틀 변경

- 정렬 표시 순서는 최신, 노출, 팔로잉, 급상승, 논쟁이다. 정렬·기간 선택은 App 메모리에 유지하고 새 실행/새로고침은 최신·오늘로 초기화한다. 기존 세션 저장소의 필터도 복원하지 않는다.
- 첨부 Pin은 공통 PinDetailCard 전체를 표시한다. 상단 지도 버튼은 해당 Pin을 조회해 지도 중심과 선택 카드로 연결한다. 삭제된 Pin과 조회 실패를 구분한다.
- 새 댓글은 support/oppose를 필수 저장한다. 좌측 지지, 우측 반대 목록에 표시하고 기존 입장 없는 댓글은 별도 목록으로 보존한다.
- 홈의 리포스트는 추가 후 내 프로필 리포스트 탭으로 이동한다. 이미 추가한 글은 그대로 이동한다. 프로필에서는 기존 취소 동작을 유지한다.
- 대표 코인은 PI로 초기화하며 수정 폼은 기존 값을 유지한다. 핀 종류·대표 코인 선택은 검색/선택 가능한 공통 앱 팝업을 사용한다. 운영체제의 권한·파일 선택·Google 로그인·설치 화면은 시스템 화면을 유지한다.

## 배틀 저장

Firebase callable `startBattle`, `finishBattle`를 `asia-northeast3`에 추가했다. 로그인 사용자가 지지/반대를 선택하면 서버가 게임 종류와 난수 시드를 발급한다. 무료 배틀이며 BP는 변경하지 않는다.

프런트와 서버는 `functions/battle-engine.js`의 동일한 엔진을 쓴다. 클라이언트는 120Hz 게임 tick별 입력을 기록하고, 서버는 시드·입력 기록·실제 경과시간으로 결과를 재계산한다. 전달받은 점수/입장은 신뢰하지 않는다. 지지 점수는 support에, 반대 점수는 oppose에 더하며 노출 점수는 support−oppose이다. 기존 실시간 피드 구독을 통해 화면과 순위를 갱신한다.

계정당 현재 게임 한 개만 유효하다. 새 시작은 이전 미완료 게임을 대체한다. 종료 결과와 게시물 점수는 한 트랜잭션으로 저장하고 동일 종료 요청/동시 재시도는 한 번만 반영한다. 삭제된 피드·30분 초과 세션·비정상 입력은 거절한다. 네트워크 실패 시 UI에서 결과 저장을 재시도할 수 있다. 클라이언트의 직접 점수/세션 쓰기는 계속 금지한다.

게임 재현은 물리적으로 가능한 기록을 검증한다. 자동 플레이 도구의 사용 여부까지 판별하는 기능은 아니다.

## 운영 반영

웹앱만 배포하면 새 배틀 함수는 호출할 수 없다. Firebase 함수와 댓글 규칙을 함께 반영해야 한다. 2026-09-19 운영 프로젝트 `koinkorae-map`의 함수 배포를 시도했으나 Blaze 종량제 요금제가 필요해 차단되었다. 요금제 변경은 수행하지 않았다. 함수 배포가 완료되기 전에는 배틀 시작·점수 반영을 사용할 수 없다.

1. Node.js 22 환경에서 `npm ci --prefix functions`.
2. 대상 Firebase 프로젝트와 Cloud Functions 사용 가능 상태를 확인한 뒤 `firebase deploy --only functions:battle,firestore:rules --project <프로젝트 ID>`.
3. 기존 GitHub Pages 웹앱 빌드·배포.

참고: [Firebase callable 함수](https://firebase.google.com/docs/functions/callable), [함수 런타임 설정](https://firebase.google.com/docs/functions/manage-functions).

## 검증

- `npm test`: 게임 재현·입력 거절·지지/반대 노출 순위·필터 초기화 포함.
- `npm ci --prefix functions` 후 `npm run test:firestore`: 로컬 Firestore 에뮬레이터에서 인증, 댓글 입장 검증, 점수 위조 금지, 함수 중복 저장 방지, 반대 점수 반영, 삭제 피드 처리를 확인한다. 운영 데이터에 연결하지 않는다.
- `npm run build`.
- 로컬 샘플 UI에서 카드, 선택 팝업, 댓글, 정렬 유지/초기화, 리포스트 이동과 배틀 결과 화면을 확인한다.
