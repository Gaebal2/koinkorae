# 친구 채팅·배틀 이어하기 배포

이번 변경은 Supabase 운영 어댑터를 기준으로 구현했다. 친구는 기존과 동일하게 서로 팔로우하는 사용자이며, 메시지 읽기·쓰기는 서버에서 친구 관계와 로그인 사용자를 확인한다.

## 배포 순서

1. `supabase/migrations/202609290001_chat_and_battle_progress.sql`을 적용한다. 메시지 저장과 배틀 진행 상태의 원자적 갱신·점수 적용에 필요하다.
2. `supabase/functions/community`를 배포한다. 기존 배틀 API도 유지하여 이전 PWA와 호환한다.
3. 새 PWA를 빌드하고 배포한다.

DB/API보다 PWA를 먼저 배포하면 새 채팅·배틀 기능이 동작하지 않는다. Firebase로 롤백할 경우 새 기능이 없는 이전 프런트엔드와 API를 함께 복원해야 한다.

## 동작

- 배틀은 시간 제한 없이 충돌할 때까지 진행한다. 서버가 짧은 구간별 입력을 재생해 점수를 검증한다.
- `게임계속`은 누적 점수를 유지하고 같은 종류의 게임을 이어서 진행한다. `점수적용`을 누를 때만 선택한 피드의 지지 또는 반대 점수에 한 번 반영한다.
- 친구 목록과 대화는 주기적으로 갱신한다. 최근 메시지 100개와 이전 대화 불러오기를 지원한다.
- 기존 Pin 분류는 화면에서 새 세 분류로 정규화하며, 편집·신규 등록에는 새 분류를 저장한다.

## 검증

`npm test`는 실제 마이그레이션을 PGlite에 적용해 메시지 접근 권한·중복 전송·이전 대화 조회·프로필 갱신·60초 초과 플레이·점수 유지·중복 적용 방지를 검사한다. `npm run build`로 PWA 빌드를 확인한다.
